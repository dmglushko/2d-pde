# Project audit — 23 October 2026

This is a historical report for commit `d576af1`. P2 support described here was
subsequently removed; the current [P1-only design](../README.md#p1-only-design)
and tests use three-node triangles throughout. The current regression suite
covers 40 shape/algorithm combinations. The findings below describe the audited
version, not the current API.

The checkout had no Git commits before this audit. The initial commit preserves
the existing library, viewer, examples, learning documents, and study guide,
together with the fixes and regression checks below. Generated LaTeX
intermediates and scratch programs are ignored and retained on disk.

## Scope and current state

Reviewed the four C++ headers, the viewer's JavaScript and example integration,
the example programs, and the learning documents. The implemented product is a
geometry/meshing library and a mesh inspection tool. Missing PDE assembly and
solver components are future implementation work, not audit findings.

The FEM study guide was inspected for project scope. Its external citations,
research claims, and numerical experiment were not independently revalidated,
and the PDF was not rebuilt (no `pdflatex` available in this environment).

## Confirmed bugs fixed

1. **Translation changed whether a valid outline could be meshed.** A `2 × 1`
   rectangle centered at `(1e9, 1e9)` was rejected as having zero area. World
   coordinate shoelace products cancelled numerically. Area/orientation now use
   differences relative to the first boundary vertex, with checks for both
   clockwise and counterclockwise outlines.
2. **Invalid outlines could return degenerate triangles.** Adjacent edges that
   doubled back, or a vertex touching a nonadjacent edge, escaped the strict
   crossing test. For example `(0,0), (2,0), (1,0), (1,1), (0,1)` produced an
   invalid mesh. Boundary validation now rejects touching/overlapping segments,
   and ear clipping checks its final triangle. Ordinary collinear boundary
   points remain supported.
3. **Optimization could exceed the requested size cap.** An irregular seven
   vertex polygon with a `0.3` target returned an edge of approximately `0.318`.
   Edge flips and smoothing now retain the global and centroid-sampled local
   size bounds established by refinement. This may skip a proposed optimization
   when it conflicts with sizing.
4. **Mesh validation accepted inconsistent edge orientation.** Two positive-area
   triangles traversing the same edge in the same direction passed import/export
   validation. The validator now rejects this local topology inconsistency.
   This check does not replace a global triangle intersection test.
5. **P2 connectivity could alias independent degrees of freedom.** A midpoint
   index could belong to distinct edges or also be a corner in another triangle.
   The validator now enforces distinct corner/midpoint roles and a single edge
   per midpoint, while preserving shared midpoint indices on common edges.
6. **Export could silently succeed after an I/O failure.** A small export to
   `/dev/full` returned success because the error occurred when the stream's
   buffered data was closed. Export now explicitly closes and checks the stream.

The mesh validator also rejects nonfinite coordinate spans and triangle area
arithmetic, rather than allowing overflow to bypass area comparisons. Removed a
duplicate assignment of the boundary node vector.

## Verification

Run `./tools/test.sh` from the project root. It covers:

- 80 combinations of eight shape cases, five algorithms, and P1/P2 order:
  positive areas, domain area preservation, structural validity, final size
  targets, midpoint positions, and exact file round trips.
- Translated outlines in both orientations, concave and collinear outlines,
  the irregular-polygon size regression, invalid boundaries, an exhausted
  refinement budget, invalid order, and invalid local sizing.
- Inconsistent shared edges, P2 aliasing and unshared midpoints, duplicate
  triangles, missing boundary records, unsupported numeric scale, truncated and
  trailing file content, and buffered write failure on Linux.
- Both C++ example programs and both bundled `.pde2d` files. The learning
  example produces 81 nodes and 128 P1 triangles; the viewer example produces
  1089 nodes and 512 P2 triangles.
- Existing viewer tests for parsing, diagnostics, quality values, selection,
  panning, cancellation, zoom, redraw, and preservation after a malformed upload.

The C++ regression executable also passed AddressSanitizer and
UndefinedBehaviorSanitizer. Viewer tests use a mocked canvas; actual browser
rendering and pixel layout were not checked. No actionable viewer bug was found
in this audit.

## Remaining limits

The importer validates local connectivity rather than proving global geometric
validity. It does not detect every overlap, require every node to be used, or
require P2 midpoint coordinates to be exactly at the straight edge center.
The viewer can flag displaced midpoints and unused nodes. Very large input
files, near-degenerate geometry, global mesh quality, and arbitrary size-field
variation have no general performance or accuracy guarantee. Refinement samples
the size field at centroids; it does not resolve every possible feature of a
callable field.

No known confirmed bug from this audit remains unfixed. This is a bounded code
review with regression checks, not a proof of numerical correctness for all
inputs.
